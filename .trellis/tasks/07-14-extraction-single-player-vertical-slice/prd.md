# Extraction 单机可玩垂直切片

## Goal

把开发入口 `?mode=single` 从 E2E 假状态预览升级为一个无需钱包、HTTP、WebSocket 或 Extraction Server 即可启动的桌面端真实第一人称体素游戏。玩家应能使用键盘和鼠标在本地世界中移动、瞄准、挖掘、管理资源、自主选择携带物并完成一次有明确结果的撤离闭环，同时不改变生产多人对局的服务端权威、安全和持久化边界。

第一阶段验证的是“进入世界 → 自主采集资源 → 返回撤离区 → 获得本局结果”的可玩性，不追求一次完成大型地图、完整美术、永久仓库或可与生产多人模式互通的存档。

## Background

### Confirmed Facts

- 当前 `?mode=single` 由 `src/testing/single-main.ts` 转入 `startE2eClient`，并继续使用装饰场景 `VoxelBackdrop`，不创建真实本地 World。
- 当前单机入口的 `movement`、`sendWorldPacket` 和 `onWorldReady` 均为空实现；挖掘和丢弃只直接修改本地 `AppState`，不执行方块射线、定时挖掘、世界修改或掉落实体（`apps/extraction-client/src/testing/e2e-main.ts:37-119`）。
- 生产客户端收到服务端 `INIT` 后才创建 `VoxelWorldSession`；该会话已包含 `World`、`RigidControls`、`Inputs`、`VoxelInteract`、Chunk 路由、玩家和掉落实体渲染（`apps/extraction-client/src/game/scene.ts:93-111`，`apps/extraction-client/src/game/world-session.ts:31-193`）。
- 真实输入控制器已实现指针锁后的移动、跳跃、挖掘、近战和整槽丢弃意图，但它把最终判定发送给生产服务端，不能原样作为本地权威玩法实现（`apps/extraction-client/src/game/world-input.ts:25-178`）。
- 生产地图、资源、生命、背包、战斗、撤离和结算均以服务端为权威。本任务不能让本地规则或假状态进入生产网络路径。
- 生产世界当前只为泥土、黄金、钻石应用纯色材质，首阶段可以复用这些资源 ID 与背包契约，但需要允许单机地图增加不产生永久资产的环境体素。
- 产品原则要求第一屏可操作、游戏画面优先、操作遵循桌面第一人称惯例，并明确区分服务端事实与本地调试状态（`PRODUCT.md:32-40`）。
- 现有工作区包含大量用户未提交修改；本任务必须限制在单机运行时及其必要共享边界，避免覆盖无关改动。

### Problem Restatement

用户现在无法在没有完整生产服务器和十人匹配的情况下直接体验 Extraction 的真实玩法，因此项目的核心交互只能通过假 HUD 或发布门禁被观察，不能作为一个独立可玩的游戏被感知和迭代。

### Fundamental Constraints

- 浏览器本地运行不能依赖可信服务器，因此所有单机结果只能是临时局内状态，不能写入永久仓库或冒充生产权威结果。
- “真正可玩”至少要求玩家的输入改变真实世界状态，并存在可理解、可完成、可失败或可重新开始的目标。
- 生产多人模式已经具有严格的网络、安全和结算边界；单机能力必须通过显式运行时边界接入，不能在生产路径中加入宽松回退。
- 第一阶段必须足够小，确保核心闭环可被自动化测试和浏览器手工验收，而不是先扩展成完整单人战役。

## Requirements

### R1. 独立单机运行时

- 第一阶段仅支持带键盘和鼠标的桌面浏览器；验收基线为 Chromium 桌面版和不小于 1280×720 的横向视口，不承诺移动端、触屏或竖屏体验。
- `?mode=single` 在开发环境中启动专用本地运行时，不再调用 `startE2eClient`，也不暴露或依赖 `window.__VOXEL_EXTRACTION_E2E__`。
- 第一阶段继续受 `import.meta.env.DEV` 保护，不进入生产构建的正式导航或未登录入口；生产开放需要在垂直切片验收后单独评审。
- 单机启动不得发起钱包、认证、匹配、HTTP API 或 WebSocket 请求。
- 单机状态只存在于当前页面内，刷新后重置；不得读取或写入永久仓库、结算表或生产账号状态。
- 页面必须持续明确标识“本地单机，不保存进度”，但提示不能长期遮挡主要视野。
- 离开、重开或热更新时必须幂等释放 World、控制器、监听器、动画帧、几何、材质和本地计时器。

### R2. 真实本地体素世界

- 单机运行时创建真实可碰撞、可射线交互、可修改的 Voxelize `World`，而不是只渲染 `VoxelBackdrop`。
- 使用固定默认种子生成小型确定性地图；同一版本和种子刷新后恢复相同初始布局。
- 首张地图采用开放天空、垂直分层的废弃采石场遗迹；地图至少包含上层出生/撤离区、普通资源层、中层黄金矿层和更深处的钻石矿层。
- 出生平台附近可以直接观察到撤离信标；玩家通过石阶、断墙、风化木梁、桥、坡道或可挖掘路径逐层向下，深入采集后需要返回上层完成撤离。
- 地图使用清晰的大型结构轮廓、高低差、遮挡和材质变化，在受控小范围内形成比现有规则采石场更高的内容密度。
- 地图必须具有可移动的地表、可向下或向内挖掘的资源层、基本高度差和不会让玩家出生后立即跌出世界的边界。
- 单机地图使用与生产清单兼容的泥土、黄金、钻石资源 ID；任何额外环境方块不得被解释为永久仓库资产。
- 第一阶段只允许挖掘泥土、黄金和钻石；石阶、断墙、木梁、桥、基岩和撤离设施等遗迹结构保持不可破坏，确保玩家始终拥有返回上层撤离区的路径。
- 瞄准可挖掘资源与不可破坏结构时必须使用不同的名称或轮廓反馈；按住挖掘键不能让不可破坏结构进入进度或产生掉落。
- 世界加载期间显示明确同步状态；初始化失败时显示可重试错误，不得停留在空白画布。
- 第一阶段使用固定温暖傍晚光照：低饱和蓝色天空、暖橙浅粉地平线、低角度暖阳、暖灰橙距离雾，以及由暖色地表逐步过渡到冷灰青深层的环境色。
- 黄金和钻石必须同时通过纹理、明度与轮廓被识别，不能只依赖黄色或青色；撤离信标使用与暖色地表对比明确的柔和薄荷绿。
- 第一阶段不实现动态昼夜循环，以固定时间和种子形成可重复的视觉验收基准。

### R3. 第一人称操作与世界反馈

- 初次进入世界时，准星附近显示极简操作提示：点击进入世界，以及 WASD、空格、按住左键、右键放置、数字键、Q、返回信标撤离等必要操作。
- 玩家首次获得指针锁后完整提示自动隐藏；`H` 可再次显示，`Escape` 释放指针锁后只显示“点击继续”，不得重播大型教程。
- 操作提示不使用欢迎弹窗、卡片或多步骤向导；减少动态效果设置下直接切换可见性，不依赖动画才能理解。
- 玩家点击场景后获得指针锁，并可使用现有桌面惯例进行 WASD 移动、鼠标视角和空格跳跃。
- `Escape` 释放指针锁；失焦、页面隐藏或结束本局时停止移动和持续动作。
- 准星射线命中真实目标方块；超出距离、被遮挡或不可采集的方块不能开始合法挖掘。
- 按住主操作键持续挖掘当前目标；松开、切换目标、离开距离或本局结束时取消并清零未完成进度。
- 挖掘完成后目标方块在 World 中只移除一次，并只产生一次对应资源。
- **有限放置（已放宽）**：选中资源槽时，右键可在准星邻格（`VoxelInteract.potential`）放置 1 个对应方块并扣减背包；工具槽（镐/剑）右键不放置。
- 放置须满足：目标格为空、在世界高度内、不可穿越块不与玩家 AABB 相交；点按立刻放置，按住约 250ms 连放。
- 不支持自由建造、Builder 工具状态、建造库存、半透明幽灵预览或社区世界规则；放置仅为局内资源闭环的补充。
- 左键继续承担挖掘与近战；右键仅用于上述有限放置，不得绕过背包守恒或复制资源。
- HUD 显示当前目标、挖掘进度、经过时间、紧凑工具/背包快捷栏和撤离状态；无敌人的第一阶段不持续显示无用途的生命条，正常情况下也不展示网络状态或 Match ID。
- 关键反馈不能只依赖颜色；指针锁、挖掘完成、背包已满、进入撤离区和本局结束必须有文字或形状反馈。

### R4. 本地资源与背包闭环

- 单机背包复用 12 格、同类堆叠优先、单格上限 64 的产品规则。
- 成功挖掘优先把资源放入背包；无法容纳的资源在世界中生成真实可见的本地掉落，而不是静默丢失。
- 玩家可选择资源槽并整槽丢弃；丢弃后生成等量本地掉落，并能通过明确规则重新拾取。
- 玩家可选择资源槽并右键放置 1 个；放置成功后背包对应槽减 1，世界只增加一次方块；失败不得扣减。
- 选中有数量的资源槽时，第一人称与第三人称自身手持显示对应方块；工具槽显示镐/剑；空槽显示空手。
- 每个资源方块和掉落实体都必须具有唯一生命周期，重复输入、重复更新或重渲染不能复制资源。
- 本地背包、挖掘和撤离状态可由专用 reducer 或 runtime model 管理，但不得伪装成已由生产服务端确认的 revision。

### R5. 可完成的单局

- 单机模式必须有一个在 HUD 中持续可理解的局内目标，而不是无限制沙盒。
- 第一阶段不包含敌人、敌人 AI、玩家受伤、战斗死亡或死亡掉落；近战装备和相关生产接口保持兼容，但不作为首阶段完成门槛。
- 玩家不需要满足资源数量、资源价值或分数门槛；撤离区可用时，即使背包为空也可以完成撤离。
- 单机模式不计算总分、目标分或排行榜；泥土、黄金和钻石只按资源种类与数量展示，不把生产仓库的统计权重解释为单机分数。
- 第一阶段没有硬截止、倒计时或超时失败；HUD 只记录从本地世界可操作开始计算的本局经过时间。
- 撤离区从开局起可见且可用；玩家进入后必须连续停留 3 秒才完成本局，离开区域会立即清零本次撤离进度。
- 撤离期间使用世界内区域反馈和轻量 HUD 进度表达，不用大型面板遮挡视野；完成时停止计时、释放指针锁并进入本地结果。
- 完成本局后显示本地结果，包括资源种类、数量、用时和结果类型，并提供“重新开始”操作。
- 本地结果必须明确标识为未保存，不能显示“永久入账”或修改生产仓库。

### R6. Create Town 参考体验与资产

- 第一阶段以 `https://create.town/lab`（及 `https://create.town/builder`）的第一人称在场感为主要视觉与操作参考，但保持 Voxel Extraction 的采集和撤离产品身份（不冒充 Create Town 品牌或世界名）。
- 参考范围不包含 Builder 的自由建造、建造库存或社区世界功能；核心交互仍以挖掘与撤离为主，**允许**局内资源槽有限放置与手持方块作为补充（对齐 Lab 键鼠惯例，不做建造沙盒）。
- 还原目标是可观察的体验特征与质量水平，包括第一人称镜头、移动观感、体素材质节奏、天空与雾、手持物（工具/方块）、目标反馈、紧凑快捷栏、轻量文字 HUD 和世界优先的视觉层级。
- **资产策略（已放宽）**：方块贴图、手持物、UI 像素素材等**不必原创**。允许从 Create Town / Lab 参考实现中**搬运、抽取并本地化使用**相关二进制贴图与可复用美术资源，以优先达到观感一致；也可继续使用程序化生成或其它来源素材作为补充。
- 搬运资产须落盘到本仓库可控路径（如 `apps/extraction-client/src/assets/single/`），由单机运行时加载，不得在运行时依赖 create.town 在线资源作为生产依赖。
- 单机对局中不显示完整产品顶栏、钱包地址、网络状态或 Match ID；这些生产信息不得占据主要游戏画面。
- 视口中央使用小型高对比准星；当前瞄准或选中的方块名称使用轻量文字标签，不使用大型面板。
- 底部使用紧凑、低高度、深色像素边框快捷栏，显示当前选择与资源数量；快捷栏不能扩展成横跨大部分视口的产品面板。
- 第一人称画面包含手部或工具 viewmodel（可搬运参考资源或自建）；挖掘、选中资源和进入撤离区必须通过世界内视觉反馈表达，而不是只更新 HTML 数字。
- 方块使用低分辨率像素纹理图集、最近邻采样和一致的纹理密度；同一方块允许顶面、侧面和底面使用不同纹理。
- 场景使用清晰天空、距离雾、环境光与方向光建立纵深；不得继续用整屏暗色遮罩把世界压成产品面板背景。
- 第一阶段只保证桌面键鼠与不小于 1280×720 的常见横向浏览器视口；移动端、触屏、虚拟摇杆、竖屏布局和小屏内容可达性均不作为本阶段实现或验收目标。
- 材质、界面、贴图、第一人称镜头、移动观感或世界反馈出现设计歧义时，优先对照 `https://create.town/lab` 的当前实际页面状态，再按 Extraction 玩法边界取舍，不凭记忆补全。

### R7. 生产隔离与兼容性

- 默认无查询参数的产品启动、钱包认证、队列、生产 WebSocket 和服务端权威 World 行为保持不变。
- E2E 模式继续使用既有 bridge 和确定性假状态，除非测试迁移计划明确替换对应覆盖；生产构建仍拒绝测试 bridge 标记。
- 单机实现优先复用纯渲染、输入、体素和无副作用规则；不得让生产客户端接受本地判定作为服务器消息。
- 新增或修改的 TypeScript 生产文件遵守 300 行软上限和 500 行硬上限；接近软上限时按运行时、地图、规则、渲染和生命周期职责拆分。
- 新行为必须补充单元测试，并至少通过客户端 typecheck、Vitest、生产 build 和边界扫描。

## Acceptance Criteria

- [ ] AC1：关闭 Extraction Server 且未配置钱包时，访问 `?mode=single` 可以进入本地世界；浏览器没有向 `/api`、`/health`、`/ws` 或钱包 provider 发起单机启动请求。
- [ ] AC1a：开发构建可以进入新单机运行时；生产构建不显示正式单机入口，也不会因 `?mode=single` 加载本地权威运行时或单机专用资产入口。
- [ ] AC2：画布在受支持桌面视口中持续渲染非空帧，玩家可获得和释放指针锁，并能移动、转向、跳跃和与碰撞体正确交互。
- [ ] AC2a：首次进入显示极简操作提示，获得指针锁后隐藏，`H` 可再次查看；释放指针锁后只显示“点击继续”，提示不会阻止画布操作或遮挡核心视野。
- [ ] AC3：固定种子地图每次刷新产生相同出生点、资源布局和撤离区；玩家不能穿出地图或出生在无支撑位置。
- [ ] AC3a：固定温暖傍晚天空、低角度光照、暖灰橙距离雾和冷暖分层在重复刷新中保持稳定；没有动态昼夜导致的截图漂移。
- [ ] AC4：准星命中合法方块后持续挖掘才会完成；取消、换目标、超距和不可采集目标均不会产生资源。
- [ ] AC4a：选中资源槽时右键可在合法邻格放置 1 个对应方块并扣 1；工具槽/空槽/非法邻格/与身体相交不得放置；不得进入 Builder 自由建造或复制资源。
- [ ] AC4b：只有泥土、黄金和钻石可以进入挖掘进度并被破坏；石阶、墙、木梁、桥、基岩和撤离设施在重复输入后仍保持不变且不产生资源。
- [ ] AC4c：快捷栏切换时第一人称手持与内容一致——槽 1 镐、槽 2 剑、有数量的资源槽显示方块、空槽空手；战斗/挖掘判定仍仅工具槽为镐/剑。
- [ ] AC5：一个方块成功破坏后只消失一次并只增加一份资源；重复输入和重复更新不能复制该资源。
- [ ] AC6：12 格背包遵守同类优先和 64 上限；满包资源形成世界掉落，整槽丢弃和重新拾取保持数量守恒。
- [ ] AC7：HUD 在 2560×1294、1440×900 和 1280×720 桌面视口中不遮挡核心操作，经过时间、工具/背包快捷栏、目标和撤离进度均可读；减少动态效果设置下仍能理解状态。移动端、触屏和竖屏不纳入本阶段验收。
- [ ] AC8：玩家可以在背包为空、只挖到一个黄金或拥有任意其他资源组合时完成撤离；结果页只展示资源种类、数量和用时，不展示分数、价值门槛或永久入账，并可一键重新开始。
- [ ] AC8a：第一阶段不生成敌人，不会伪造 PVP 伤害、战斗死亡或死亡掉落数据，也不存在硬截止、倒计时或超时结果；经过时间从玩家可操作后单调累计。

## Out of Scope

- 永久单机存档、云存档或单机资源同步到账号仓库。
- 钱包、SIWE、匹配、十人对局和生产服务器规则的重新设计。
- 让本地客户端成为生产多人对局的权威来源。
- 完整大型手工地图、程序化洞穴系统、多生物群落或商业级美术素材库。
- 制作、交易、装备成长、任务树、剧情战役和完整新手教程。
- 第一阶段的敌人 AI、PVE 战斗、受伤、死亡掉落和 PVP 模拟。
- 移动端浏览器、手机和平板触屏操作、虚拟摇杆、触摸挖掘、竖屏布局与小屏适配。
- Create Town 的品牌名、世界名称、聊天、社区导航，以及 Builder 自由建造/建造库存/社区世界（**局内有限放置与贴图搬运允许，见 R3/R6**）。
